홀센서 2개만 확인하기 — TRAIN 전용

현재 보류: 추가 홀센서를 찾지 못해 실물 시험은 아직 진행하지 않았다. 이 안내와 코드는 부품을 찾은 뒤 사용한다. 기존 센서 1개 구성은 유지한다.

기존 센서는 유지하고 새 DRV5055A3QLPG 한 개를 추가해 LCD에서 각각 확인한다. 버튼 조작·PSD 업로드는 필요 없다. 기존 통합 코드와 서보·모터 시험 코드는 수정하지 않았다.

1. 전원을 끄고 새 센서 연결

아래 MCU 번호는 TRAIN ATmega328P DIP-28 칩의 실제 다리 번호다. PSD나 USBasp 커넥터 번호가 아니다.

새 DRV5055A3QLPG 센서의 핀 연결
1번 VCC TRAIN의 기존 5V 전원선
2번 GND TRAIN의 기존 GND 전원선
3번 OUT TRAIN 칩 24번 = PC1 = Arduino A1

기존 센서 OUT은 TRAIN 칩 23번 = PC0 = A0 그대로 둔다. 두 센서의 5V/GND는 공유하지만 OUT끼리는 연결하지 않는다. 새 센서의 VCC–GND 사이에 0.1µF 세라믹 커패시터(104)를 센서 가까이 연결한다.

위는 구입한 LPG/TO-92 패키지의 핀 번호다. SOT-23이나 다른 홀센서의 핀 배열과 혼동하지 않는다. 방향은 같은 모델인 기존 센서 및 제조사 그림과 대조한다. TI DRV5055 데이터시트, 3쪽 그림 4-2 및 핀 표.

2. TRAIN에 시험 코드 업로드

  1. 모터·서보 전원을 분리한다. USB 전원을 공유한 서보는 전원을 끈 상태에서 서보 전원 연결을 분리한다. MCU·LCD·홀센서의 5V/GND는 유지한다.
  2. PSD는 꺼 두어도 된다. 켜 둔 통합 PSD가 통신 FAULT를 표시하더라도 이번 독립 시험의 판정 대상이 아니다.
  3. 이 폴더의 train_hall_test.ino를 연다. 같은 폴더의 lcd_safe.h도 그대로 둔다.
  4. 기존처럼 보드 Arduino Uno, 프로그래머 USBasp를 선택하고 프로그래머를 사용하여 업로드한다. 퓨즈·부트로더는 변경하지 않는다.

코드는 TRAIN 모터(칩 5번)와 서보(15·16번)를 LOW로 유지한다. 무선 송신·운행 순서·FAULT 판정·자석 개수 자동 판정은 없다. 기존 LCD 배선(27번 SDA / 28번 SCL, 주소 0x27)을 그대로 사용한다.

3. LCD를 보면서 시험

표시 예시이며 숫자는 실제 측정값으로 바뀐다. 약 0.2초마다 8회 평균 ADC 값(0–1023)을 표시한다.

H1 P23 A= 508
H2 P24 A= 512
  • H1: 기존 센서, H2: 새 센서. P23/P24는 TRAIN 칩 핀 번호다.
  • 자석 없음: 각자 약 512 부근에 안정되는지 기록한다. 기존의 508과 정확히 같을 필요는 없다. DRV5055는 자석이 없을 때 출력이 전원의 약 절반이다. TI 데이터시트.
  • 새 센서에 자석 1개 접근: H2가 변하고, 멀리 치우면 원래 값 부근으로 돌아오는지 본다. 극을 뒤집으면 반대 방향으로 변해야 한다.
  • 기존 센서에도 같은 시험: H1이 같은 방식으로 반응하는지 확인한다. 한 센서만 시험할 때는 다른 센서를 자석에서 충분히 떨어뜨린다. 둘 다 가까우면 두 값이 함께 변하는 것이 자연스럽다.
  • 2개·3개 묶음: 같은 극·거리·위치를 유지하며 각각의 값을 기록한다. 부품은 자석의 개수가 아니라 자기장 세기를 측정하므로, 새 센서에 기존 판정 범위를 그대로 적용하지 않는다.

끝의 !는 ADC가 5 이하 또는 1018 이상이라는 참고 표시다. 자석을 멀리 치워도 0/1023 근처에 계속 붙으면 전원을 끄고 모델·VCC/GND/OUT·연결 위치부터 확인한다. 선이 빠진 입력도 그럴듯한 숫자가 나올 수 있으므로 숫자가 뜨는 것만으로 합격은 아니다.

LCD가 멈추거나 안 나오면 I2C 배선을 확인하고 전원을 다시 켠다. LCD 통신이 막히면 화면 갱신을 중단하도록 되어 있다. PC 시리얼 출력은 선택 사항이며 LCD 시험에는 필요 없다. USBasp 자체는 시리얼 모니터 연결을 제공하지 않는다.

4. 알려줄 값

조건 기존 H1 새 H2
자석 없음
자석 1개, 한쪽 극 / 반대 극
자석 2개, 한쪽 극 / 반대 극
자석 3개, 한쪽 극 / 반대 극

각 센서에 같은 조건으로 따로 대어 기록한다. 새 센서의 변화·극 반전·원래 값 복귀가 확인되면 2번째 홀센서의 기본 시험 성공이다. 아직 이동 중 위치 판정이나 2개 센서를 사용하는 통합 운행 검증은 아니다.

시험 후 가상 운행 순서 시험으로 돌아갈 때는 기존 train_sketch를 다시 업로드한다. 그 코드는 여전히 H1 하나만 읽으며 모터·서보는 꺼져 있다. H2를 통합 판단에 사용하는 변경은 이번에 하지 않았다.

코드 확인 결과

Arduino Uno 컴파일 성공: 플래시 7,062바이트, SRAM 515바이트. 컴파일한 펌웨어의 모의 실행에서 A0/A1 독립 입력, LCD 행·핀 번호·ADC 표시, 양방향 변화·복귀, 범위 끝의 !, 버튼 무시, LCD 통신 시간초과 후 ADC 측정 지속, 모터·서보 OFF 및 무선 비활성 상태를 확인했다. 재검증용 파일은 tests/run_dual_hall_gpio.cjs다. 실제 보드 업로드 및 새 센서의 실물 시험은 아직 수행하지 않았다.
